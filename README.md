# 门店低销预警台

区域值班经理用本地工作台处理门店日销，对照**上年同星期营业日**找出持续走弱的门店，并在第一天收到可干预信号。

自然日期映射四四五财周，按「同财周序号 + 同星期」取上年基准；本年销售额严格小于基准的 80% 记为走弱。单个门店一天只采信最高修订版本。

## 核心规则

1. **首日信号**：同一门店累计 2 个走弱营业日即触发，触发日就是第 2 个走弱日。
2. **跨周不拆段**：连续区间按自然日扫描，不按财周切断；跨财周下滑保持一个区间，月结再按财周归因。
3. **单日缺口不算下滑、也不拆段**：连续 1 个停业/缺报日不断区间；连续第 2 个不可比日才断开；达标营业日立即断开。
4. **坏行不丢记录**：列宽、必填、状态、版本冲突等逐条隔离并写明原因，输入行数全程闭合。
5. **迟到数据不倒退**：新版本只允许区间向后延伸；若迟到补报使区间缩短或消失，保留原结论并追加留痕（`LATE_DATA` / `NOT_REPRODUCED`）。
6. **确认即锁定**：批次确认后，已确认门店与区间不可改写、不可新增（新区间拒收并记 `BLOCKED_LOCKED_STORE`）；同一批字节重跑幂等。
7. **依据可查**：每个预警可查触发日、上年基准日、走弱日、缺口日、财周序号和连续可干预区间。

## 启动

```sh
docker compose up --build
```

打开 http://127.0.0.1:18306 并运行随附样例。可在「导入日销与门店清单」上传自己的 CSV，也可直接编辑表单样例。数据保存于 Compose 卷 `ledger`，`APP_PORT` 可覆盖宿主端口。

## 工作步骤

1. 在「日销送报」检查编码、列宽与来源行，定位坏行、空白行和重复表头。
2. 在「字段归一」查看修订、营业状态与归一后的日销字段。
3. 在「版本冲突」区分同版冲突、旧版替代与重复传输。
4. 在「走弱检测」查看每个营业日的基准、阈值与走弱判定。
5. 在「低销预警」查看连续区间、触发日和依据，必要时「确认本批」锁定月结归因。
6. 在「预警批次」复算历史批次，在「值班确认」登记处理意见并下载证据。

接口定义见 `/openapi.json`。字段、原因码与算例见 [数据字典](docs/DATA-DICTIONARY.md)，模块与回归测试见 [测试登记](docs/DEPTH.md)。

## 验证

```sh
docker compose config --quiet
docker compose exec -T app pytest -q
```

`sample_data/shift.csv` 是日销样例，`sample_data/external.csv` 是门店清单。`cases.csv` 固定单日判定算例，`legacy.csv` 与 `truncated.csv` 验证历史编码与断行，样例由 `tools/make_samples.py` 生成。
